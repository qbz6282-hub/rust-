# 開發紀錄

本文件由原本寫成一大段散文的 README 整理而來，保留原意，只補上標題與結構。逐字原文另存於 `docs/00_原始說明.md` 與 `docs/01_第二分支說明.md`。

## 1. 起點：第一版

- 完全沒有使用 AI 協助，由一位高職二年級資訊科學生寫成。
- 依賴只有四個：`reqwest`、`serde`、`serde_json`、`tokio`，且都採用當時最新版本。
- 此時只做到「把對話請求送給模型、把回覆印出來」。

## 2. 想加「代碼編寫」工具，但碰到權限問題

後續的更新方向是讓模型能寫程式碼。但很快就發現一個關鍵風險：

> 讓模型在主要環境（本機）直接執行寫碼工具，權限過大，電腦裡不該被變動的資料可能被改掉。

因此改用 **WSL 連接 Podman** 這個免費沙箱環境，把執行隔開。Podman 需依自身系統下載安裝包；作者是 Windows / x86，選的是 **MSI** 安裝包。

## 3. 模型沒有工具呼叫能力

- `main.rs` 本身已實際跑過、可編譯可執行。
- 但本機的模型都沒有訓練過工具呼叫能力，所以工具一直用不起來。
- 改試 OpenRouter 的免費模型，卻常態回 `400` / `429`（額度幾乎用盡）。

這也是後來加入「工具請求可選開關」的原因：對不支援的模型送 `tools`，Ollama 會直接回 `400 ... does not support tools`。

## 4. 第一次成功：`機緣巧合而適配.py`

呼叫 `baidu/ernie-5.5-flash-preview:free` 時，模型依據給它的「編寫代碼」工具，在預設資料夾裡寫出了 `main.py`。

有個有趣的插曲：明明要求用 Rust 寫，第一次卻產出 Python。作者推測是第一次忘了先開啟 Podman 沙箱，導致工具無法使用；第二次把沙箱開起來後，模型就寫出了那份腳本，命名為「機緣巧合而適配」。該腳本現在放在 `examples/model_generated_multiply.py`，內容是在沙箱裡建立一個计算 `9178 × 6769` 的 Rust 小專案並編譯驗證。

## 6. 現行版做了什麼

- 三種後端（OpenRouter / Ollama / LM Studio）收斂到同一份內部格式。
- 工具請求改成可選，並用 Ollama `/api/show` 的 `capabilities` 自動判斷。
- 回覆正規化、零拷貝反序列化、單元測試。

## 7. 教訓

1. **API Key 不要寫進原始碼或設定檔後直接上傳**：早期版本確實這麼做過，舊金鑰應至 <https://openrouter.ai/keys> 撤銷。
2. **檔案要有副檔名、專案要有 `Cargo.toml` 與 `src/`**：否則 GitHub 不會上色、IDE 不認得、`cargo` 也無法編譯。
3. **分支名稱用簡單英文**：中文句子含全形逗號，會讓 clone、checkout、網址都變得麻煩。
